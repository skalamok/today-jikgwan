# 발표에 쓸 이야기

발표 자료(13장)는 이미 만들어져 있다. 이 문서는 **자료에 아직 안 들어간 것** 가운데
말할 값어치가 있는 것을 모아 둔 것이다. 12장 "구현하니 드러난 설계 누락" 에 붙이거나
질문을 받았을 때 꺼내면 된다.

## 12장에 넣을 후보

### 1. PATCH 인데 실은 전체 치환이었다

기록 수정을 `PATCH /attendance-logs/{logId}` 로 냈다. 요청에 없는 필드가 지워진다는 것을
모르고 비용 없이 보냈다가 **실제로 기록의 비용이 날아갔다.** 통산 지출이 252,000원에서
159,000원으로 줄어서야 알았다.

부분 갱신이 아니므로 `PUT` 이 맞다. 화면은 언제나 전체 폼을 보내므로 동작은 그대로다.
**메서드 이름이 곧 약속인데 그 약속을 잘못 골랐다.**

> 제출한 명세는 PATCH 다. 구현하면서 드러난 것이라 저장소에만 반영했다.

### 2. 지우기 전에 읽는다

`REQ-NF-007` 은 업로드 즉시 위치를 포함한 메타데이터를 지우라고 한다.
`REQ-F-204` 는 사진의 촬영 시각으로 경기를 골라 주라고 한다. **둘이 부딪힌다.**
서버가 지운 뒤에는 촬영 시각도 없다.

서버에서는 풀 수 없어 브라우저로 옮겼다. 지우기 전에 읽어 경기 후보를 고르는 데만 쓴다.
라이브러리는 넣지 않았다. 필요한 것은 `DateTimeOriginal` 하나뿐이라 파일 앞 128KB 만 본다.

### 3. 외부 데이터는 붙여 봐야 안다

`TheSportsDB` 에 KBO 리그가 있고 약관상 수집도 허용된다. 인터페이스를 만들고 실제로 켜 봤다.
경기는 3건 돌려주는데 **전부 걸러졌다.**

```
Hanwha Eagles vs Doosan Bears @ Daejeon Hanbat Baseball Stadium
```

구단과 구장이 영문 표기라 우리 데이터와 맞지 않는다. 이름 대응표를 만들고 계속 유지해야
쓸 수 있다는 뜻이다. **"이용 조건은 확인했지만 도입은 미뤘다" 가 추측이 아니라 확인한 결과다.**

## 문서를 만들며 배운 것

말할 자리가 있으면 꺼내고, 없으면 넘긴다.

- **문서끼리 어긋나는 것은 눈으로 못 잡는다.** 부록 표의 열이 한 칸 밀려 범위 값이
  인증 칸에 찍혀 있었고, 발표 자료에는 이미 지운 테이블이 남아 있었다.
  정합성 검사를 27항목까지 늘린 이유다 (`tools/check_consistency.py`)
- **손으로 적은 수치는 반드시 낡는다.** 그래서 테이블 목록 · API 목록 · 규모 · 쪽수를
  전부 원본에서 생성하도록 바꿨다
- **인쇄 크기를 먼저 계산해야 한다.** A4 세로 178mm 에서 6pt 를 얻으려면 원본 폭이
  900px 을 넘으면 안 된다. ERD 를 세 번 다시 그린 이유다

## 데모 순서 (제안)

1. 사진 한 장 올리기 → 날짜 · 경기가 저절로 채워진다 (REQ-F-204)
2. 좌석 고르고 별점 → 저장
3. 전적 화면 → 통산은 1경기부터, 나눈 집계는 5경기부터 (REQ-F-305)
4. 구장 상세 → 내가 남긴 평가가 다음 사람에게 보인다 (REQ-F-110)
5. 기록 상세 → 직관 카드 저장 (REQ-F-704)

시간이 모자라면 1과 3만 해도 "기록하면 전적이 된다" 는 한 줄이 성립한다.
