# 2. 기술서 API 설계 장의 예시 수정 (제출본과 달라진 부분)

**제출한 기술서에는 틀린 값이 들어 있다.** PART 5 의 요청 · 응답 예시 세 개 중 둘이
실제 스키마와 맞지 않았다. 값을 확인하지 않고 그럴듯하게 적은 것이다.
서버를 띄워 실제 응답을 받아 그대로 옮겼다.

| 예시 | 제출본에 적힌 것 | 실제 |
|---|---|---|
| 기록 중복 409 | `DUPLICATE_LOG` | `DUPLICATE_ATTENDANCE_LOG` + `data.existingLogId` |
| 전적 요약 200 | `{ total, byStadium }` 중첩 | 평평한 응답. 차원별은 `GET /stats/me` 로 분리 |
| 메이트 신청 201 | `{ applicationId, seq, status }` | `{ seq, confirmedCount, capacity }` |

정원 초과 오류 코드도 문서에 없던 `CAPACITY_FULL` 대신 실제인 `COMPANION_POST_FULL` 로 적었다.

**발표 때 이 세 화면은 띄우지 않는다.** 제출본은 바꿀 수 없으므로 질문을 받으면
값이 실제와 다르다는 것을 먼저 말하는 편이 낫다.

# 정합성 검사에 더한 것

위 오류들은 눈으로 잡히지 않아 검사를 늘렸다.

| 항목 | 무엇을 보는가 |
|---|---|
| 발표 자료의 식별자 실재 | 슬라이드가 말하는 REQ · SCR 번호가 문서에 있는가 |
| 발표 자료의 기술서 쪽수 | 슬라이드에 찍힌 쪽수가 실제 PDF 쪽수와 같은가 |
| 문서의 오류 코드 실재 | 문서에 적은 `code` 가 `ErrorCode` 에 있는가 |

`DUPLICATE_LOG` 처럼 있을 법한 이름은 읽어서는 걸리지 않는다.
기존 항목과 합쳐 **27개**이며 모두 통과한다.

```
python3 tools/check_consistency.py
```
