### 1.1.1 날씨 데이터 (2026-08-18 추가 검토)

경기 데이터와 동일한 절차로 확인했다.

| 출처 | 가부 | 근거 |
|---|---|---|
| **기상청 단기예보 조회서비스** (공공데이터포털) | **채택 (1순위)** | 무료, 자동승인. 활용신청 즉시 인증키 발급 확인 (2026-08-18) |
| 기상청 기상특보 조회서비스 | 채택 | 우천 취소 가능성 안내(REQ-F-113)에 사용 |
| 기상청 API허브 (apihub.kma.go.kr) | 대체 경로 | 기상청 직접 운영. 무료, 자동승인, 일 20,000건/5GB 한도 명시. 레이더·위성 등 데이터 범위가 더 넓다 |
| 민간 날씨 사이트 크롤링 | 불가 | 경기 데이터와 동일한 이유 |

**공공데이터포털을 1순위로 둔 이유**: 두 창구가 제공하는 예보 데이터는 사실상 동일하며 둘 다 자동승인이다.
공개된 예제와 참고자료가 많아 구현 비용이 낮은 쪽을 선택했다.
API허브는 호출 한도가 명시되어 있고 레이더·위성까지 다루므로, 향후 데이터 범위를 넓힐 때 전환 대상이 된다.
**어느 창구를 쓰든 REQ-F-107 의 제공자 인터페이스 뒤에 두므로 구현체 교체만으로 전환할 수 있다.**

예상 호출량은 경기 5건 × 1일 4회 배치 = 약 20건으로, 어느 창구의 한도로도 충분하다.

**경기 데이터와 대조되는 지점**: 같은 절차로 확인했으나 결과가 달랐다.
공공기관이 이용 조건을 명시해 개방한 데이터는 문제없이 사용할 수 있다.
**출처를 확인하는 절차 자체가 문제가 아니라, 확인 결과에 따라 설계를 맞추는 것이 요점이다.**

### 2. STATIZ 문의 및 확인 결과 (2026-08-18)

당초 STATIZ가 공개한 "데이터 이용 시 출처를 명시하라"는 안내를 근거로 이용이 가능하다고 판단했다.
그러나 그 안내가 어디까지 적용되는지 명확하지 않아 운영자에게 직접 문의했고, 다음을 확인했다.

- **크롤링을 통한 데이터 수집을 금지한다.**
- **개인 이용자에게 제공할 수 있는 API 가 없다.**

수집 방법을 조정해서 해결되는 문제가 아니라 **개인이 이용할 수 있는 정식 경로 자체가 존재하지 않으므로**,
해당 출처를 배제했다.

**시사점**: 외부 데이터를 설계에 넣기 전에 두 가지를 순서대로 확인해야 한다.

1. 개인 개발자가 이용할 수 있는 **정식 경로가 있는가**
2. 그 경로가 우리가 필요로 하는 **이용 방식을 허용하는가**

공개된 안내 문구를 해석하는 것은 그다음 문제다. 본 프로젝트는 이를 설계 단계에서 확인하여
구현 이후에 발생했을 문제를 예방했다.

### 3. robots.txt 확인 (2026-08-18)

이용약관과 별개로 각 사이트의 로봇 배제 표준을 확인했다.

**koreabaseball.com/robots.txt**

| User-agent | Disallow |
|---|---|
| Googlebot, Yeti, Daumoa, Bingbot | `/ws/` |
| `*` (그 외 전체) | `/` — 사이트 전체 |

**statiz.co.kr/robots.txt**

| 항목 | 내용 |
|---|---|
| Content-Signal | `search=yes, ai-train=no, use=reference` |
| Googlebot, Yeti, Bingbot | 허용, `Crawl-delay: 5` |
| AI 크롤러 12종 (GPTBot, ClaudeBot, CCBot, Google-Extended, anthropic-ai, Claude-Web, PerplexityBot, Bytespider, Amazonbot, Applebot-Extended, meta-externalagent, FacebookBot) | `/` |
| `*` (그 외 전체) | `/` |

두 사이트 모두 지정된 검색엔진 외의 모든 User-agent에 대해 사이트 전체를 차단하고 있다. 본 서비스가 운영할 수집기는 `*` 에 해당하므로 전면 차단 대상이다.

**해석 시 유의점**: robots.txt 는 기술적 관례이고 이용약관은 계약이므로, robots.txt 가 허용 신호였더라도 약관의 금지 조항을 뒤집지 못한다. 본 건은 두 근거가 일치하여 해석의 여지가 없다.

### 4. 검증 절차 요약

데이터 이용 가능 여부를 다음 세 단계로 확인했다.

| 단계 | 방법 | 결과 |
|---|---|---|
| 1 | 이용약관 확인 | KBO 제14조 차항 — 자동화 수집 및 타 플랫폼 연동 금지 |
| 2 | robots.txt 확인 | 두 사이트 모두 `User-agent: *` 에 대해 `Disallow: /` |
| 3 | 권리자 직접 문의 | STATIZ — 크롤링 금지, 개인 이용자용 API 없음 |

세 근거가 모두 같은 결론을 가리키므로 **웹 페이지를 긁어 오는 방식은 배제한다.** 대신 약관이 명시적으로 허용하는 공식 API 를 찾아 1차 출처로 삼는다.

### 5. 채택안 — 외부 공식 API + 사용자 제보 이중 구조

#### 5.1 1차 출처: TheSportsDB 공식 API

| 항목 | 내용 |
|---|---|
| 제공 데이터 | Korean KBO League (리그 ID 4830), 10개 구단 및 홈구장, 경기 일정 및 결과 |
| 이용 근거 | 이용약관 — "You can scrape, copy and modify any content returned from the API, as long as you use the official end points." |
| 본 프로젝트 이용 티어 | **무료 (V1 API, 분당 30회)**. 무료 티어는 경기 데이터를 15건으로 제한하므로 구단·구장 확보에 사용하고, 경기 데이터는 사용자 제보와 시드 데이터로 대체한다. 데이터 자체는 완전함이 실측으로 확인되어 유료 전환 시 즉시 해소된다 |
| 제약 | 무료 티어는 공용 테스트 키(`123`)를 사용하며 호출 한도를 전체 무료 사용자와 공유한다. 앱스토어 배포는 유료 구독 필요 (웹 배포는 제한 없음) |
| 금지 사항 | API 자체의 재판매 금지 |

#### 5.2 2차 출처: 사용자 제보

외부 API의 데이터가 누락되거나 부정확할 수 있으므로, 사용자 제보를 검증·보완 수단으로 병행한다.

| 상황 | 처리 | 요구사항 |
|---|---|---|
| 외부 API에 결과가 있음 | 해당 값을 확정 결과로 사용 | REQ-F-107 |
| 외부 API에 결과가 없음 | 사용자 제보를 수집하고, 기준 수 이상 일치 시 확정 | REQ-F-606, REQ-F-607 |
| 외부 API 값과 제보가 불일치 | 운영자 검토 대상으로 표시 | REQ-F-607 |
| 어느 쪽도 확정되지 않음 | "확인 중" 상태로 표시 | REQ-F-608 |

관람 기록 작성자만 제보할 수 있으므로 제보 신뢰도가 확보되며, 외부 API 단일 의존을 피할 수 있다.

### 6. 설계에 미치는 영향

| 항목 | 영향 |
|---|---|
| 경기 일정 · 결과 (REQ-F-101 ~ 103) | 외부 API 배치 동기화로 확보. 운영자 수동 등록 부담 해소 |
| 팀 순위 (REQ-F-104) | 동기화된 경기 결과로부터 직접 산출 |
| 실시간 스코어보드 (REQ-F-105) | 유료 구독 전제. 본 프로젝트는 화면 정의까지만 수행 |
| 호출 한도 (REQ-N-016) | 분당 30회 제한이 있으므로 화면 요청을 외부로 직접 전달할 수 없다. 서버 배치 동기화 + 캐시가 필수 설계 요소가 된다 |
| 사용자 제보 (REQ-F-606 ~ 608) | 삭제하지 않고 검증·보완 수단으로 유지. 외부 API 단일 의존 회피 |
| 관람 기록 · 전적 · 구역 만족도 | 영향 없음. 본래 사용자가 생성하는 데이터 |
