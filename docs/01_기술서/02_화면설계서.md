## 작성 범위

전체 화면 24개 중 아래 7개를 상세 설계 대상으로 한다. 각 화면은 모바일 기준으로 작성하며, MVP 나머지 화면의 와이어프레임은 8장, 데스크톱 배치는 9장에 있다. 나머지 화면은 요구사항 정의서 2장의 화면 목록으로 정의를 대신하며, 본 문서 11장에 개요만 기재한다.

| 순번 | 화면 ID | 화면명 | 범위 | 선정 사유 |
|---|---|---|---|---|
| 1 | SCR-AUTH-001 | 로그인 | MVP | 서비스 진입점 |
| 2 | SCR-MAIN-001 | 홈 대시보드 | MVP | 사용자 상태에 따른 분기 로직 |
| 3 | SCR-GUIDE-001 | 첫 직관 가이드 | 확장 | 신규 사용자 유입 경로 |
| 4 | SCR-PARK-002 | 구장 상세 | MVP | 쌓인 기록이 다른 사용자에게 보이는 지점 |
| 5 | SCR-LOG-001 | 직관 기록 작성 | MVP | 서비스 핵심 기능, 입력 검증 최다 |
| 6 | SCR-STAT-001 | 내 전적 요약 | MVP | 집계 결과의 표시 정책 |
| 7 | SCR-MATE-002 | 메이트 모집글 상세 | 확장 | 선착순 확정에 따른 상태 변화 |

그레이스케일로 작성하며 레이아웃 · 정보 구조 · 동작 조건에 집중한다. 색은 상태 구분에만 제한적으로 쓴다.
화면 내 각 요소에는 ①②③ 식별 번호를 부여하고, 아래 디스크립션 표의 NO 와 1:1로 대응시킨다.

## 0-2. 전 화면 공통 규칙

| 구분 | 정의 |
|---|---|
| 레이아웃 | 모바일을 기본으로 한다. 헤더(화면명 · 알림 · 프로필), 바디, 하단 탭(홈 · 경기 · 기록 · 전적 · 계획 · 구장)으로 구성하며, 운영자에게는 운영 탭이 추가된다. |
| 로딩 | 데이터를 불러오는 동안 스켈레톤을 표시한다. 버튼 동작 중에는 버튼을 비활성화하고 스피너를 띄운다. |
| 네트워크 오류 | 하단에 "네트워크 연결을 확인해 주세요" 토스트를 띄우고 재시도 버튼을 제공한다. |
| 서버 오류(5xx) | 전체 화면 오류 페이지를 띄우고 새로고침 버튼을 제공한다. |
| 인증 만료(401) | "로그인이 만료되었습니다" 토스트를 띄우고 SCR-AUTH-001 로 이동한다. 이동 전 화면 경로를 보관해 로그인 후 그 화면으로 돌아온다. |
| 권한 없음(403) | "권한이 없습니다" 토스트를 띄우고 직전 화면을 그대로 유지한다. |
| 빈 상태 | 목록이 비어 있으면 안내 문구와 다음에 할 일을 함께 보여준다. 예를 들어 "아직 기록이 없어요" 와 [첫 기록 남기기] 버튼을 함께 노출한다. |
| 외부 데이터 표기 | 외부에서 받아온 데이터를 표시하는 영역 하단에 제공처를 고정 노출한다. 현재 경기 데이터는 운영자가 직접 등록하므로 표기 대상이 아니며, 날씨는 `출처 : 기상청` 을 표기한다 (REQ-NF-014, REQ-NF-024). |
| 이미지 | 목록에서는 썸네일을, 상세에서는 원본을 불러온다 (REQ-NF-002). |

| 동일 시간대 중복 참여 | 같은 시간대 다른 경기에 이미 확정돼 있으면 "같은 시간에 확정된 약속이 있어요"를 안내하고 신청을 거부한다 (REQ-F-505). |
| 본인 모집에 참여 시도 | [참여하기] 대신 [모집 마감하기] 를 노출한다 (REQ-F-503). |
| 경기 시작 24시간 이내 취소 | "경기 임박 시에는 취소할 수 없어요"를 안내하고 취소를 막는다 (REQ-F-506). |
| 경기 시작 시각 경과 | 상태를 종료로 전환하고 모든 동작을 막는다. |
| 비로그인 참여 시도 | 로그인 화면으로 보내고, 로그인하면 이 화면으로 돌아온다. |
| 확정 후 대화 진입 | 확정 상태에서만 [대화방] 버튼을 노출하며, 누르면 SCR-MATE-003 으로 이동한다 (REQ-F-511). |
| 신고 | 모집글 · 댓글 · 확정된 메이트를 신고할 수 있다 (REQ-F-508). |

## 8. MVP 화면 와이어프레임

MVP 13화면 가운데 상세 설계를 작성한 7개를 뺀 나머지다. 디스크립션 표까지 만들지는
않았고, 화면 안 요소의 동작 조건은 와이어프레임의 주석으로 대신한다.
각 화면이 어느 요구사항을 구현하는지는 10장 표와 요구사항 정의서 2장에서 확인한다.

### 8.1 SCR-AUTH-002 회원가입

![SCR-AUTH-002](../_assets/wireframes/SCR-AUTH-002.png)

필수 약관에 동의하기 전에는 가입 버튼이 활성화되지 않는다. 응원팀은 여기서 고르지 않아도
마이페이지에서 설정할 수 있다.

### 8.2 SCR-GAME-001 경기 일정 · 결과

![SCR-GAME-001](../_assets/wireframes/SCR-GAME-001.png)

결과가 등록되지 않은 경기는 스코어 자리에 "확인 중"을 표시해 확정된 경기와 구분한다.

### 8.3 SCR-PARK-001 구장 목록

![SCR-PARK-001](../_assets/wireframes/SCR-PARK-001.png)

로그인한 사용자에게는 구장마다 본인 전적을 함께 보여준다. 기록이 없으면 "아직 없어요"로
표시하고 승률은 내지 않는다.

### 8.4 SCR-LOG-002 내 기록 목록

![SCR-LOG-002](../_assets/wireframes/SCR-LOG-002.png)

목록에서는 썸네일만 불러온다. 원본은 상세 화면에서 로드한다 (REQ-NF-002).

### 8.5 SCR-LOG-003 기록 상세

![SCR-LOG-003](../_assets/wireframes/SCR-LOG-003.png)

비공개로 설정한 기록도 본인은 티켓 카드를 만들 수 있다. 공개 범위는 서비스 안에서 남에게
보이느냐의 문제이고, 내 기록을 내가 이미지로 내려받는 것은 별개다.

### 8.6 SCR-MY-001 마이페이지 · 배지

![SCR-MY-001](../_assets/wireframes/SCR-MY-001.png)

미획득 배지도 조건과 함께 흐리게 보여준다. 무엇을 하면 받을 수 있는지 알아야 다음 기록을
남길 이유가 된다.

## 9. 데스크톱 레이아웃 (반응형)

REQ-NF-012에 따라 모바일을 기본으로 설계하되, 넓은 화면에서는 정보 밀도를 높이는 방향으로 전환한다.
전환 기준을 900px 로 둔 것은 사이드바(232px)를 빼고도 본문이 2단을 유지할 수 있는 최소 폭이기 때문이다.
아래 규칙은 전 화면에 공통으로 적용하며, 화면별 데스크톱 와이어프레임은 1~7장 각 화면의
와이어프레임 절에 모바일 판과 나란히 실었다.

| 구분 | 모바일 (< 900px) | 데스크톱 (>= 900px) |
|---|---|---|
| 컨테이너 폭 | 480px | 최대 1400px |
| 내비게이션 | 하단 고정 탭 | 좌측 고정 사이드바 (232px) |
| 본문 배치 | 1단 세로 스크롤 | 2단 그리드. 1180px 이상에서 3단 |
| 주요 액션 버튼 | 가로 전폭 | 최대 320px |
| 전적 요약 카드 | 일반 카드 | 가로 전폭 (`grid-column: 1 / -1`) |

**폼 성격의 화면(SCR-AUTH-001 로그인, SCR-AUTH-002 회원가입, SCR-LOG-001 기록 작성)은
데스크톱에서도 단일 컬럼을 유지한다.** 입력 순서가 곧 작성 흐름이므로 다단으로 나누면
사용자가 어디까지 채웠는지 잃는다. 넓어진 폭은 폼 자체를 키우는 데만 쓰고 나머지는
여백으로 흘려보낸다.

상세 설계 대상 7화면은 모바일과 데스크톱 와이어프레임을 모두 작성했다.
8장의 MVP 화면은 모바일 판만 작성하며, 위 공통 규칙을 그대로 따른다.


## 10. 추적성 확인

각 화면의 디스크립션에 매핑된 요구사항 ID를 화면 단위로 모은 것이다.

추적성은 두 방향으로 유지한다. **요구사항 → 화면**은 요구사항 정의서의 `관련 화면 ID · NO`
열에서, **화면 → 요구사항**은 각 화면 디스크립션 표의 `매핑 요구사항 ID` 열에서 확인한다.
상세 설계가 있는 화면은 화면 ID 뿐 아니라 디스크립션 번호까지 대조된다.

### 11.1 SCR-AUTH-004 소셜 로그인 콜백 처리 규칙

상세 설계는 작성하지 않았으나, 화면이 아니라 **처리 규칙**에 가까운 부분이라 동작만 정리한다.

| 상황 | 처리 |
|---|---|
| 사용자가 동의 화면에서 취소 | "○○ 로그인을 취소했어요"를 안내하고 로그인 화면으로 돌아가는 링크를 제공한다. |
| 인가 코드 없음 | "인증 정보가 없어요"를 안내한다. |
| 보관한 `state` 와 응답 `state` 불일치 | "인증 요청이 확인되지 않았어요"를 안내한다. 이 브라우저에서 시작한 요청이 아니므로 진행하지 않는다. |
| 정상 · 응원팀 있음 | 원래 가려던 경로로 돌아간다. |
| 정상 · 응원팀 없음 | 마이페이지로 보내 응원팀부터 고르게 한다. 전적 판정 기준이 되기 때문이다. |

### 11.2 SCR-ADM-001 운영자 화면 구성

| 탭 | 내용 |
|---|---|
| 결과 미등록 | 이미 시작했으나 결과가 등록되지 않은 경기를 모아 보여준다. 관람 기록 건수를 함께 표시해 처리 순서를 판단하게 한다. |
| 경기 등록 | 일시 · 구장 · 홈 · 원정을 입력한다. 홈과 원정이 같거나 같은 날 같은 구장에 중복 등록하면 거부한다. |
| 구장 · 구역 | 구역을 추가하고 이름을 바꾸거나 비활성으로 돌린다. 관람 기록이 0건인 구역에만 삭제 버튼이 노출된다. |

권한이 없는 사용자는 좌측 메뉴에 항목이 표시되지 않으며, 주소로 직접 진입해도 잠금 안내만 보인다.
